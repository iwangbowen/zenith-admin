# 维护模式接入与验证

能力与协议以 [维护模式](../../../../docs/backend/maintenance-mode.md) 为唯一规范，契约在
`shared/src/ops/contracts/maintenance.ts`；不要另建开关或公开恢复接口。

1. 复用 Service 全局锁、当前时段和递增版本，写入原因与变更过程；预计结束与自动恢复独立。
2. 新增例外在 `maintenance-access-policy.ts` 按方法和完整模板声明，诊断与中间件共用判定。
3. 查看、管理、日志与业务通行分别校验；认证检查当前账号、角色和会话撤销，不能仅信任 JWT 角色。
4. 多入口提示使用公开状态缓存与统一错误标识，恢复时失效业务缓存；检查失败保留凭证。
5. 计划进入系统调度，通知进入统一 Outbox；重试与过期计划不得影响其他时段，活动记录不参与保留清理。
6. 验证并发、版本冲突、权限、计划提醒/开始/取消/恢复、HTTP/WS、本地恢复，并做浏览器与窄屏回归。

全局中间件或认证变更执行全量 Server 测试；契约变化审查领域与完整路径快照。
多入口和首屏依赖变化检查构建、bundle budget 与生产 smoke。
