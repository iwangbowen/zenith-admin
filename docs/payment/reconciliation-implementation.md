# 生产对账实施记录

本轮按渠道账户重建对账闭环，统一交易、资金与银行到账核验。用户要求分阶段提交，全部实施后统一运行迁移验证、构建、静态检查、测试和浏览器实测。

## 阶段与提交边界

1. 渠道账户及精确金额：稳定账户身份、认证版本、资金事实关联和共享契约。
2. 账单证据与任务底座：不可变原件、版本、标准明细、账期覆盖和异步执行。
3. 渠道接入：微信、支付宝、银联下载、完整性校验和专用格式解析。
4. 自动对账：支付/退款核对、缺失账期补跑、差异案件及查单补偿。
5. 人工处置：审批调整、执行防重、证据冻结和冲正。
6. 资金及到账：Journal 核验、银行流水导入、多对多到账分配。
7. 财务工作台：业务页面、查询缓存、通知、权限、Mock、文档。
8. 统一验收及修复：迁移、构建、lint、自动化测试、真实浏览器功能验证，最后推送。

## 必须保持的不变量

- 一个渠道账户一次取得完整账单，应用归属依据交易事实确定。
- 原件来源、摘要、版本和原始行号可追溯；解析失败不等于空账单。
- 金额全程使用精确最小货币单位；支付与每次退款是独立事实。
- 对账运行冻结输入，重跑保留历史；账期完成与案件结案分别管理。
- 下载失败可补跑；发现差异不直接改余额；查单补偿复用支付确认链。
- 调整申请与审批分离，过账再次校验证据，状态和凭证在同一事务提交。
- 正式账单、已发布结果、案件历史与凭证不得级联删除。
- 任务运行依托任务中心，业务通知依托通知 Outbox。
