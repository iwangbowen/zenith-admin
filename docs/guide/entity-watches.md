# 对象关注与业务变化提醒

关联视图提供图标形式的关注入口。首批支持支付订单、退款、流程实例、设备、设备告警和异步任务；没有可靠业务事件的对象不显示入口。关注从当前时刻开始，不补发过去事件。

通知默认进入站内信，可在个人通知偏好中启用邮件或关闭该事件。邮件继续遵守免打扰、摘要窗口与通知策略。点击提醒直接进入事件来源详情，使用与前端关联下钻共用的安全路由目录。

## 可靠事件与派发

`entity_watches` 保存当前用户的对象关注。`recordDomainEvent()` 与业务更新同事务保存领域事件、subjects 和 `entity_watch_events` 待派发记录。任务成功、失败、取消以及 IoT 告警触发、认领、手动/自动恢复均走此边界。

启动时注册的 `entity-watch-delivery` 系统任务每分钟处理待派发记录，也可在调度中心手动执行。每轮最多运行 40 秒、200 个批次，每批读取 20 个关注。租约令牌隔离并发 worker；通知入队与逐关注进度同事务提交。失败按退避重试，进程退出后租约到期继续处理。没有全局事件 ID 高水位，因此较小 ID 的事务晚提交也不会遗漏。

事件的 source 和 subjects 共同匹配关注，通知按事件、收件人去重。用户同时关注订单和退款时，同一次退款事件只产生一条提醒。通知自身的 queued/dispatched/failed 元事件不进入关注派发，避免递归。

## 权限与取消

入队前与实际渠道发送前都重新检查用户启用状态、当前有效角色与菜单权限、租户活性和归属、模块许可、数据范围、关注对象及事件来源的可见性。后台派发使用当前数据库权限快照，不沿用用户关注时的旧角色或权限缓存。

取消全部匹配关注、删除对象、禁用用户或撤销权限后，尚未开始投递的提醒会被抑制，投递日志记录 `source_unavailable`。重新关注不会激活之前延后的旧事件。已开始执行的外部渠道发送与已经送达的消息不会撤回。

延后的邮件继承事件标识，实际发送仍执行同一授权检查。关注邮件在用户选择的摘要窗口到点后逐条发送，不进入会丢失对象授权边界的通用摘要 HTML；继续执行当前偏好和免打扰判断。

## 接入新对象

先接入真实领域事件：业务状态与安全摘要事件必须同事务写入，source/subjects 来自已授权业务记录，去重键表示真实业务事实。随后在 `WATCHABLE_ENTITY_TYPES` 中开放对象，并在共享详情路由目录登记精确详情入口。没有详情路径或缺少可靠事件时保持不开放。

验收覆盖事件晚提交、业务事务回滚、重复事件、多对象关注去重、取消后延后提醒抑制、权限即时撤销、通知偏好以及来源详情跳转。Demo 模式支持关注状态以及支付/退款成功、订单关闭、流程终态、任务终态和设备告警变化的站内信演示；真实邮件、租约恢复和权限撤销语义以服务端测试与本地浏览器验收为准。
