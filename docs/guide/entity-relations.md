# 跨对象关联视图

关联能力是平台的对象上下文读模型，与统一搜索并列。搜索负责找到对象；关联面板展示经过授权的相关记录，时间线展示结构化业务事件。详情、SideSheet 与搜索结果复用同一套组件，没有独立菜单。

## 对象与模块接入

`shared/core/entity-ref.ts` 定义 `EntityRef { type, key }` 和带角色的 `SubjectRef`。对象 key 是最长 128 字符的 URL 安全不透明字符串；数字主键使用标准十进制，复合键由所属模块编码。引用不携带客户端可选的租户。`shared/platform/entity-catalog.ts` 是无运行依赖的类型清单，`entity-registry.ts` 提供对应校验 schema；`ENTITY_RELATION_TYPES` 仅标记当前实际具备服务端解析器的对象，搜索类型通过显式映射引用实体类型。

每个业务模块贡献独立的 `EntityAnchorResolver[]` 与 `RelationProvider[]`。平台装配时拒绝重复 key、缺少来源/目标解析器、描述 key 不一致。解析器负责锚点权限及真实租户，Provider 负责本域关系语义和目标可见性 SQL。平台不接受表名、SQL、归属列等客户端输入。

当前覆盖：

| 锚点 | 领域关系 |
| --- | --- |
| 支付订单 | 退款、投诉、落单后风控命中、审核、对账调整审批、会计凭证、对账案件与调整、分账、结算批次、已验证渠道回调 |
| 退款、投诉、风控记录 | 反向支付订单 |
| 会计凭证、对账案件与调整、结算批次 | 反查订单与退款；结算沿逐笔分录关联凭证，案件关联调整，调整关联实际入账凭证 |
| 分账单、接收方与冲正 | 订单、接收方、分账与冲正双向查询，凭证沿明确的记账来源关联 |
| 渠道回调 | 已验签且处理成功的回调反查支付订单 |
| 用户 | 本人归属的后台支付订单 |
| 会员 / 钱包流水 / VIP 续费履约 | 会员、支付订单与实际入账 / 续费记录双向查询；履约详情显示余额或延期结果 |
| 请假单、CMS 内容、对账调整单 | 历次审批、各轮审批附件与归档件；流程按领域权限反查原业务单据 |
| 流程实例 / 审批任务 | 审批任务、子流程、所属实例、同一业务的其他轮次、受控附件与归档件 |
| 审批附件 / 归档件 | 由真实来源引用反查所属审批，附件还可定位所属任务；文件预览沿工作流专属权限接口 |
| 设备 / 告警 / OTA 任务 / 固件 / 设备升级结果 | 告警及所属设备；沿任务、固件与单设备执行记录追溯升级 |
| CMS 内容 | 同站点已定义的相关文章 |
| 网盘文件 / 文件夹 | 上级目录、子项，复用节点 ACL |
| Wiki 文档 | 上级文档、子文档，复用空间与草稿权限 |
| 知识文档 / 公告 / 业务附件 | 文档与公告的受控附件，以及同一托管文件的可见业务引用；托管文件 UUID 与网盘节点 ID 分别授权 |
| 异步任务、通知、操作审计 | 从结构化 subjects 反查来源业务对象，逐个授权后去重与分页 |

所有已接入锚点另有通用操作审计、通知、异步任务和人工关联分组，按目标领域权限发现。用户与会员是不同身份；不根据整数 ID 相等推断绑定。支付风控在订单创建前发生且尚无订单身份的记录，不会归入后来恰好使用同一业务编号的订单。会员尚未产生明确履约映射的支付记录也不会被猜测归属。

## 契约、分页与授权

契约在 `shared/platform/contracts/entity-relations.ts` 与 `entity-timeline.ts`。

```text
GET    /api/platform/entities/{type}/{key}/relations
GET    /api/platform/entities/{type}/{key}/relations/{sectionKey}
GET    /api/platform/entities/{type}/{key}/timeline
POST   /api/platform/entities/{type}/{key}/links
DELETE /api/platform/entities/{type}/{key}/links
GET    /api/platform/entities/{type}/{key}/watch
POST   /api/platform/entities/{type}/{key}/watch
DELETE /api/platform/entities/{type}/{key}/watch
```

描述接口返回可见锚点、分组和定性 `summaryState`，不查询计数。常见分组以带完整可见性谓词的 `EXISTS` 合并为每批最多 8 组的 SQL；多态关系仍通过有界目标授权扫描判断存在性。单连接上的查询串行执行，批量或单组失败由 savepoint 回滚隔离；剩余预算不足时只将尚未完成的分组标记为 `unavailable`。

组内按主键倒序在 SQL 中取 `limit + 1`；时间线按事件发生时间、来源类别和 ID 稳定倒序。公开游标加密、认证并绑定用户、模拟登录、当前租户视角、真实锚点租户、对象和分组；每次请求仍重新授权。禁止把分页游标当成授权凭据。

分组通过 `filters` 声明关键词、状态选项、时间范围及仅需处理的支持能力。筛选在授权 SQL 的 LIMIT 前执行，未支持的条件返回 400；多态目标在有界授权扫描内过滤并保留继续游标。游标认证范围绑定规范化筛选，不能跨条件复用。时间线支持事件类型及日期范围。筛选后的空结果不会覆盖原分组摘要；空页但扫描尚未结束也不会被标为无记录。

`attention` 检查整个可见集合，不以最新一条代替：退款待审批或失败/结果未知、投诉未处理/处理中、风控待审核、运行中流程确有待审批任务、通知和后台任务失败、操作日志响应码不小于 400。历史风控命中、正常执行中的任务不自动视为异常；未定义处理规则的关系仅提示有无记录。

来源业务对象分组按 `(entityType, entityKey)` 的 C 排序序列分页，同一对象的多个角色只展示一次。不可见、已删除或尚未接入的目标被跳过；扫描具有批次和总预算，不暴露隐藏对象计数。多领域来源分组不会因其中一个无关领域未授权而整体消失。

锚点不存在、不可见、未接入或功能授权不可用时统一 404。无发现权限的分组不返回。领域表的租户条件还要叠加锚点真实租户，平台管理员全租户视角也不能混入另一个租户的业务键。受限数据范围缺失归属列会报错，不能回退成全量。

关系列表只选择摘要字段，完整表单、投诉正文、通知收件地址、请求体、任务 payload 等不进入关联 DTO。目标详情再次鉴权。未知事件类型不进入时间线；领域事件的来源对象还会重新解析授权。

每个进程最多同时处理 8 个关联读请求，不建立无界队列；查询使用只读事务，PostgreSQL statement timeout 为 1500ms、lock timeout 为 750ms，多次查询还有总时间/扫描预算。已完成锚点和分组授权后的单组 SQL 超时返回可重试的降级状态；系统性故障返回 503。Prometheus 记录关联查询耗时与成功/失败/超时结果。

## 关系事实与写入

已有外键和经领域确认的业务键继续作为权威事实，不复制为通用图。支付订单的审批关联沿订单→对账案件→调整单→流程业务键查询，不能简单匹配不含应用作用域的 `bizType/bizId`。

财务关联沿实际记账来源、外键与结算逐笔分录，约束租户、应用、渠道账户和币种；不按金额或日期推测关系。渠道回调仅在验签通过、处理结果为 `processed:*` 且应用与渠道配置匹配时关联订单；原始请求体和请求头不进入摘要。尚未生成凭证的调整显示空态，退款回调没有持久化的精确退款身份时不推测关联。

业务审批映射由 `shared/platform/workflow-business-catalog.ts` 声明。历次审批按 `bizType + bizId + tenantId` 查询，不依赖业务表只指向最新轮次的实例指针。流程来源和每一个目标各自授权；流程监控权限不会自动授予他人的请假单、CMS 编辑或财务单据权限。请假和对账调整支持按主键打开原业务页，流程使用独立实例深链。

`workflow.attachment` 以 `workflow_attachment_links.id` 为 key，保留具体实例、任务/评论/表单字段来源，`fileId` 外键指向受控文件。输入只接受 `fileId`，输出名称、大小、类型与访问 URL 均由服务端生成；不解析或兼容旧 URL。明细表文件按声明字段解析，业务侧聚合附件使用 `(instanceId, attachmentId)` 签名游标跨轮次分页。隐藏字段在 SQL 内过滤。

`workflow.archive` 以拥有归档槽的实例 ID 为 key，沿 `archiveFileId` 外键读取。原件列表、详情和下载同时考虑流程参与者权限、节点隐藏字段与 PII 脱敏；下载明确请求 `source=archive` 并验证 SHA-256，不回退为当前版式。完整附件生命周期见[业务模块接入工作流](../workflow/business-integration.md#受控附件与归档)。

`entity_relation_edges` 仅存人工 N:M 关系。受控目录提供对称的相关对象，以及有方向的补充材料、参考依据、后续处理；反向展示材料用于、被引用于和前置事项。关系说明、建立人和真实建立时间随关联返回。同一对象对的不同类型关系可共存，解除时明确类型与方向。服务端校验双方存在、可见、同租户并禁止自关联。读时再次授权两端，不返回不可见目标的计数。`system:relation:manage` 控制维护，添加和解除都记审计；管理者可幂等解除已删除目标的旧引用。

`operation_log_subjects`、`notification_outbox_subjects`、`async_task_subjects` 和 `domain_event_subjects` 将副作用与业务对象结构化关联，`traceId` / `parentRef` 只描述请求因果。父行与 subjects 一起提交；事务 API 要求传入真实业务租户，不能在平台全租户视角下自动写 null。

两类记录的耐久性不同：

- 请求操作日志保留现有 `setImmediate` 尽力记录模式。日志和 subjects 原子写入，失败记录服务端错误；进程在异步任务运行前退出仍可能缺失请求快照。
- 用于业务生命周期的领域事件与支付 outbox、流程 outbox、通知或异步任务同事务写入，重放按幂等键校验业务事实和主体集合。摘要只允许 `domain-events.ts` 目录声明的字段，不能透传业务 payload。

`domain_events` 默认保留 365 天，可使用既有保留策略管理；subjects 随父记录级联清理。操作日志、通知和任务继续沿用各自生命周期。

## 前端与缓存

`EntityContextView` 组合关联区与独立时间线，保留领域自身概览。标题仅用图标提示状态，通过 Tooltip 与无障碍标签解释，不展示数量或额外状态文字。分组首次展开才请求，支持刷新、重试和继续加载；刷新控件连同 Tooltip 包裹层固定在内容区右上角，不进入标题点击区、不占一行，也不在刷新时插入顶部加载元素。

筛选图标在展开内容内打开筛选区域；空分组可统一隐藏。筛选状态复用 `useListSearch`，下钻后可恢复。服务端按当前业务状态和处理权限提供处理入口，前端进入原生退款审批、任务处理、告警或流程详情；列表与详情复用业务动作，原模块继续负责确认、幂等与写入鉴权。时间线事件可点击来源对象，任务及通知的终态事件与真实状态同事务保存。

已注册详情路由的关联对象进入精确 ID 详情，其他对象在同一个关联抽屉内导航。会话内返回栈按登录用户、租户视角和模拟登录身份隔离；保存来源对象引用并重建已消费的详情参数，同时恢复关联页签、展开分组、详情滚动位置和通用 `useListSearch` 的筛选草稿、提交条件、分页。页面自身的其他交互状态继续由 KeepAlive 或页面已有 URL 规则管理。返回入口只有一个，置于当前弹层的焦点范围内，不能在遮罩后不可点击。普通菜单导航、退出登录或身份切换结束这次关联浏览；整页刷新不持久化导航栈。

query key 从契约派生，再加入有效用户、租户视角和模拟登录身份。跨域变更使关系缓存失效；人工关联操作刷新两端。后台统一订阅实际支付、流程、任务、站内信和设备事件，以 200ms 合并窗口刷新活跃关系查询；只更新进度数值的任务推送不重复触发。无可靠推送的变更由前台活跃查询每 30 秒校准，后台窗口或隐藏页面暂停，恢复焦点和连接时回源；刷新保留已有内容。Demo handlers 绑定同一契约并使用真实 Demo 数据。

来源摘要 `origin.explanation` 描述公开的关联依据，`eventType` 只包含安全事件标识；`relatedAt` 只在实际持有关系建立时间时填写。`occurredAt` 是业务记录时间，不能将两者混称。来源说明不承载事件 payload、地址或完整表单。

请求指标区分成功、权限拒绝、繁忙、预算耗尽、超时与错误；摘要指标包含分组状态和批次/回退查询耗时。标签只使用注册的实体/关系类型与有限状态，不包含对象 ID、租户 ID 或用户数据。

审计、任务、通知投递及各财务列表复用公共关联列。通知投递行使用 `outboxId` 定位通知对象，没有 outbox 的记录不显示该入口。财务及任务状态变更统一使关联缓存失效。

## 新模块清单

1. 注册规范实体类型；只有解析器和页面都完成才加入实际支持清单。
2. 提供轻量的可见锚点解析器，返回真实租户，不取完整详情中的敏感字段。
3. 以命名空间 key 声明关系，复用所属领域 ACL/数据范围；SQL 内完成过滤和分页。
4. 在业务 Service 已持有授权后的行时登记审计 subjects；创建通知和任务时显式传主体与租户。
5. 需要时间线时向事件目录增加安全摘要与权限，在业务事务内写事件。
6. 页面挂载公共组件，变更 hooks 声明关系缓存失效，Demo 使用同一契约。
7. 覆盖无权限、跨租户、模拟登录、重复时间戳分页、删除及幂等重放测试。

基础入口不会自动补全所有领域的通知/任务历史或推断关系。未接入的写入点按上述清单逐模块登记，不做字符串解析、历史回填或双读兼容。

可靠业务事件支持[对象关注与变化提醒](./entity-watches.md)。详情路由由 Shared 的 `entity-detail-routes.ts` 统一提供给前端与通知；没有可靠事件的对象不显示关注入口。本轮实施范围见[业务处理增强计划](./entity-relations-next-phase.md)。
