# 顶部统一搜索实施计划

顶部搜索框是唯一交互入口。菜单结果继续来自当前用户可见的菜单树，业务结果通过
`/api/platform/search` 返回摘要 DTO；服务端每个适配器在自己的 SQL 查询中追加租户、数据范围和领域权限。

统一契约和编排层不随业务模块重复修改。新增模块只需要：

1. 在 `globalSearchTypes` 增加类型；
2. 实现 `GlobalSearchAdapter`，声明所需列表权限；
3. 在搜索注册表注册适配器；
4. 为适配器补权限、租户、数据范围和详情边界测试。

实施切片：

- C1：统一契约、适配器注册表、超时/失败隔离、顶部搜索框壳层和菜单结果。
- C2：用户、会员；验证租户、数据范围和摘要字段最小化。
- C3：支付订单；只返回订单号、主题和状态等安全摘要。
- C4：工作流实例；普通列表权限只搜索本人可见实例，监控权限才使用监控数据范围。
- C5：IoT 设备和告警；设备租户条件与告警设备租户条件必须一致。
- C6：网盘文件；复用节点 ACL，下载能力单独判断，全文正文后置。
- C7：CMS 内容、Wiki 文档、公告管理；复用站点 / 栏目 / 空间 ACL，正文只用于召回，不进入统一摘要。
- C8：业务单据、报表资产和聊天消息；聊天优先复用现有消息搜索服务。
- C9：AI 知识库、任务中心、操作日志、异常日志和关系摘要，按敏感等级逐个追加。

各切片单独提交。完整构建、测试、浏览器 QA 和权限矩阵在全部切片完成后统一执行。
