# 跨对象关联视图：业务处理增强

本轮承接已完成的摘要、导航、来源和刷新基础，直接在 `master` 分阶段提交；不维护历史兼容分支。实现期间补齐必要测试用例，全部功能完成后统一执行测试、lint、build、包体预算、启动冒烟及浏览器回归。

## 阶段 1：检索与聚焦

关联分组支持关键词、业务状态、时间范围与仅需处理。过滤在服务端覆盖完整可见集合，游标签名绑定筛选条件；各 Provider 声明自身支持的过滤能力。面板支持隐藏空组，筛选无结果与原始分组为空分开表达，保留图标状态与稳定刷新布局。

## 阶段 2：业务处理入口

需处理记录提供明确的处理入口，进入原模块的审批、任务重试或告警处理详情。权限、确认、审计、幂等与写入规则继续由原业务服务负责，处理完成使关联缓存失效。不会在关联模块另建一套业务写操作。

## 阶段 3：可下钻时间线

时间线支持事件类型和时间范围过滤，通过事件来源引用进入精确详情并保留返回上下文。补齐异步任务终态与通知投递结果的结构化事件，事件和实际状态在同一事务提交，事件内容保持安全摘要。

## 阶段 4：三条完整业务链

1. 会员 → 钱包充值 / VIP 续费履约 → 支付订单，提供双向关联和精确详情。
2. 设备 → OTA 任务 → 固件 → 单设备执行结果，沿明确外键追溯。
3. 知识文档 / 公告 → 业务附件 → 可见引用位置，分别授权业务对象、托管文件和网盘节点。

## 阶段 5：人工关联语义

人工关联使用受控类型、方向和说明，展示建立人及真实建立时间。类型目录明确允许的语义，系统自动关系仍由业务事实维护；建立和解除记录审计，两端访问权在读取和写入时重新验证。

## 阶段 6：对象关注提醒

允许用户关注可见的业务对象，通过已有通知中心接收关键业务变化。使用可靠事件处理、去重与有界分页，发送前重新验证关注者对对象和事件来源的权限，复用通知偏好和免打扰策略；通知指向精确详情，取消关注后停止后续提醒。

## 统一验收

- 筛选命中位于首屏之后的数据；筛选改变后旧游标失效；跨租户 / 无权限目标不可见。
- 从关联进入处理、事件来源或新增业务链详情，再返回原对象，恢复筛选、页签与展开位置。
- 人工关联正反方向、类型与说明正确；解除后两端更新。
- 关注与取消关注、重复事件去重、权限撤销、通知偏好关闭均有验证。
- 桌面和窄屏页面保持标题仅状态图标、不展示数量、刷新不跳动。
