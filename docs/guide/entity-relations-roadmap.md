# 跨对象关联视图优化路线图

本路线图按阶段提交。阶段内只完成实现和代码提交，统一在全部阶段完成后执行 build、lint、测试和浏览器回归。

## 阶段 1：摘要查询性能与处理状态

- 关联分组摘要只返回 `has-data`、`empty`、`attention`、`unavailable`，不返回数量。
- Provider 优先实现 `summaryQuery()` / `prepareSummaryQuery()`，以复用权限条件并参与批量 SQL；特殊 Provider 可使用 `exists()` / `summarize()`，均未实现时才使用同权限的 `list(limit=1)` 兜底。
- 摘要查询按最多 8 组 EXISTS 合并 SQL，单个事务连接内保持串行，savepoint 隔离失败并遵守总预算。
- 为退款待处理、投诉未解决、通知失败、审批待办等场景登记 `attention` 规则。

## 阶段 2：关联导航返回栈

- 关联对象进入精确详情时保留来源 URL、页签、筛选和滚动位置。
- 目标详情支持返回原对象上下文，不重复堆叠 SideSheet。
- 导航栈保留在当前会话内并限制深度，以身份隔离；返回按对象引用重建精确详情参数，通用列表保存筛选草稿、提交条件和分页。

## 阶段 3：来源语义

- 统一展示 direct、derived、causal、activity 关系的来源语义。
- 关系项在允许范围内展示来源事件、来源时间和触发原因摘要。
- 保持摘要 DTO 最小化，敏感 payload、请求体和收件人信息不进入关联视图。

## 阶段 4：领域覆盖审计

- 按 identity/member、workflow/tasks、iot/content、drive/wiki 和 audit 逐域审计锚点、Provider、详情路由、权限和 Mock。
- 只补充有明确业务事实的关系，不按 ID、金额、日期或字符串猜测关系。
- 每个领域完成反向查询、跨租户隔离、删除目标和无权限目标检查。

## 阶段 5：一致性与缓存

- 关系建立 / 解除和已接入的业务事件统一将关系查询标为过期，仅活跃查询立即回源，覆盖无法在客户端枚举的反向关联。
- 详情页支持后台重新验证，刷新期间保留已有内容和布局。
- 为关系摘要、列表和时间线定义清晰的 query key 与失效边界。

## 阶段 6：观测与最终验收

- 增加摘要耗时、关系查询耗时、降级、超时、权限拒绝和空结果指标。
- 完成响应式、键盘、无障碍、浏览器深链、刷新稳定性和权限矩阵回归。
- 全部阶段完成后统一运行 build、lint、Shared / Server / Web 测试、启动冒烟和浏览器验收；包体预算不因本功能直接放宽。

## 实现边界

领域覆盖先盘点现有 Provider，补齐确实缺失的 IoT 告警详情 API、设备/告警深链、处理权限及 Demo；会员、工作流、任务、内容、网盘和审计复用已实现关系，不重复创建 Provider。未保存的业务关联不作推测。

`attention` 已落在退款待审批/失败/未知、投诉待处理/处理中、风控待审核、实际审批待办、失败通知/后台任务及失败操作日志；其他关系默认只判断有无数据。外部通知投递没有稳定推送时，活跃面板按 30 秒周期校准。

通用 `useListSearch` 的筛选与分页可跨页面卸载恢复；设计器、表单草稿等页面私有交互不进入关联栈。导航栈不写持久存储，整页刷新或结束关联浏览会释放。
