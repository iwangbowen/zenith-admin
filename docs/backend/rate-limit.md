# 接口限流

接口限流保护管理后台、会员和公开 HTTP 入口，规则目录、提交契约与管理页面共用当前标准。开放平台套餐的 QPS/日/月配额及工作流连接器的出站限流保持各自职责，不合并计费或熔断语义。

## 规则与执行

- 内置规则在 shared 的 rate-limit-policy.ts 声明一次，启动时初始化缺失配置，数据库保存覆盖；读取列表不产生写入。内置规则不可删除，可编辑或停用。
- IP / IP+资源规则在认证前执行；身份规则仅在各认证器验证成功后执行。管理员、会员和开放应用分别使用 u:租户:ID、m:租户:ID、a:租户:clientId，平台租户标记为 platform；匿名请求不回退到用户额度。
- 同一请求每规则仅应用一次。认证前和认证后各选一条路径规则，优先级大者优先，同值按规则名稳定排序；业务具名保护可以叠加，管理页的路径诊断明确不覆盖全部业务具名链路。
- 路径支持 {id}、:id、单段 * 和末尾 /*，支持 /api/ 与 /s/ 入口；HTTP 方法空集表示全部方法。匹配逻辑由 shared 纯函数供执行、诊断和 Demo 共用。
- 主窗口与附加窗口在单次 Redis Lua 内计数并判定；所有尝试计入窗口，拒绝请求不回退计数。固定窗口从首次请求计时，滑动窗口为两桶加权近似，等待时间考虑下一次尝试及历史桶衰减。
- 计数规格包含算法、窗口、身份维度、方法和路径范围；修改计数规格不混用旧窗口。临时封禁不绑定计数规格，修改普通限额不解除封禁。

## 配置与安全

规则管理使用全局配置，多租户部署要求平台管理员；单租户部署按功能权限授权。查看、管理规则、封禁和清理分别使用 system:rate-limit:view、manage、ban、reset 权限。

新建自定义规则默认停用、观察模式；停用规则可作为草稿保存，启用自定义规则必须绑定路径。无匹配接口不意味着非法，因为显式挂载或部署特有路径不一定出现在契约目录。过宽路径覆盖限流管理或健康探针时拒绝启用，避免锁死恢复入口。

规则保存持久化后刷新当前进程；PostgreSQL 事务提交触发 cache_invalidate，其他 API 实例在后续请求重载。广播断线、重连和丢通知由重置及30秒兜底刷新覆盖，不承诺所有实例在保存响应之前加载完成。页面分别展示配置版本和当前实例加载状态。

Redis 判定使用独立有界命令客户端，命令超时750毫秒，不离线排队。规则可选择故障放行或故障拒绝；后者返回503、Retry-After及 X-Zenith-Error: rate-limit-unavailable，不能触发前端全站维护。只有明确 maintenance 标识的503才进入维护展示。429附带退避时间，额度响应头经 CORS 暴露给调用方。

公开链接或会话令牌不进入限流记录：展示安全路由模板，按资源隔离的计数身份使用路径摘要。IP来自现有可信代理解析器，不信任未受信来源伪造的转发头。

## 临时封禁与运维

启用规则内，显式临时封禁优先于普通豁免和观察模式；停用规则不再执行该策略。封禁必须记录原因、操作人和到期时间，到期由Redis TTL解除。

“清除额度”只清除当前计数规格各窗口；“解除封禁”只删除显式封禁；“清空统计”切换统计周期，不改变计数或封禁。所有管理动作经过契约权限及操作审计，不删除历史命中记录来掩盖一次额度重置。

## 统计和页面

- 运行概览统计最近24个小时桶的规则命中量，区分实际拒绝、观察命中、临时封禁、豁免及故障决策；同一HTTP请求可触发多个保护层，不能将规则命中合计当作唯一请求数。
- 遥测使用最多2000条内存队列、每批500条异步写入，不在请求链逐条写数据库。队列和写入异常允许丢弃，并在页面暴露当前实例待写及丢弃量。
- 小时桶保留25小时，日桶32天；近期异常决策每规则最多500条，7天到期；今日来源排行最多1000个身份，保留2天。记录使用独立ID避免同毫秒事件覆盖。
- 清空统计切换周期，所有小时/日趋势、近期记录和来源排行同时从新周期读取；旧周期按TTL自然回收，清理前已入队事件不能回灌新周期。
- 列表查询只取摘要，详情按需加载30天趋势与Top来源；命中记录服务端筛选、分页，明确它是有界近期诊断记录而非完整审计日志，可按关联ID跳转现有API访问日志。
- 页面分规则管理、运行概览、命中记录和临时封禁；配置侧栏基本信息、接口范围及主限额展开，高级窗口、豁免、故障和告警折叠。窄屏保留完整标签与固定操作区，关键计数不省略。
- 匹配诊断不修改额度，不执行请求、不接受伪造身份作为真实授权，仅解释输入上下文下的路径选择；并发额度、具名保护及实际身份仍由真实请求决定。

## 接入与验收

新增保护优先复用具名规则或方法与路由绑定，不自行创建第二套通用限流表或队列。API契约位于 shared/platform/contracts/rate-limit.ts；前端通过契约查询层获取规则、接口目录、诊断和统计。

验收覆盖模板与通配路径、方法、相同优先级、跨租户/身份隔离、多窗口并发、配置变更、封禁与豁免、观察转拦截、Redis超时及恢复、统计清理与保留期、公开令牌不泄漏、双实例失效传播，以及桌面和390px页面实际操作。集成测试使用隔离前缀和fixture并清理，不修改已有生产规则做压力试验。
