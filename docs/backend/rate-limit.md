# 接口限流

接口限流管理页面为 `/system/rate-limit`，统一管理 HTTP 入口的规则、匹配诊断、运行统计和临时封禁。规则策略存储在 PostgreSQL，计数、封禁及有界统计存储在 Redis。

本能力与[开放平台限流套餐](../open-platform/scopes-rate-limits.md)分工：接口规则负责入口防滥用，套餐负责应用 QPS 和日/月配额；工作流连接器的出站限流保护下游。各保护层可以共同生效，但不合并计费、配额或熔断语义。

## 规则来源与配置

内置默认规则集中定义在 `packages/shared/src/platform/rate-limit-policy.ts`，seed 与运行时共用。API 启动时初始化缺失的内置配置并加载规则；列表查询只读，不初始化数据。数据库配置覆盖默认策略，内置规则可编辑或停用，不可删除。

规则名称是不可变标识，创建后不能改名。配置通过 shared 契约校验，Service 复验豁免身份、保护范围、窗口组合和告警接收人。

| 配置项 | 规则 |
| --- | --- |
| `name` | 1–64 字符，以小写字母开头，只允许小写字母、数字、下划线和连字符 |
| `description` / `blockedMessage` | 可空，最多 255 字符；未配置拦截文案时使用统一提示 |
| `windowMs` / `limit` | 主窗口 1 秒至 24 小时，上限 1–1,000,000 次，均为整数 |
| `extraWindows` | 最多两个附加窗口，取值范围与主窗口相同；所有窗口时长必须不同 |
| `methods` | GET、POST、PUT、PATCH、DELETE、HEAD、OPTIONS；空集表示全部方法 |
| `pathPatterns` | 最多 50 项，每项最多 256 字符，以 `/api/` 或 `/s/` 开头，不含查询参数、片段或空白 |
| `priority` | 0–9999，控制同一执行阶段的路径规则选择 |
| `allowlist` | 最多 100 项；支持有效 IP、CIDR 和计数身份，非法值在保存时拒绝 |
| `failMode` | `open` 为故障放行，`closed` 为故障拒绝；缺省放行 |
| `alertThreshold` | 当前小时实际拦截阈值，1–1,000,000；空值表示不告警 |
| `alertUserIds` / `alertCooldownSeconds` | 最多 20 个启用的平台用户；冷却 60–86400 秒，缺省 3600 秒 |

管理页新建规则默认停用、观察模式，可先保存为草稿。启用自定义规则必须绑定路径；内置具名保护不要求额外路径绑定。没有匹配的契约目录项不等于无效规则，非契约入口和部署特有路径需结合实际挂载核对。

启用范围匹配到 `/api/rate-limit/rules` 或 `/api/health/readyz` 时拒绝保存，避免过宽配置覆盖管理恢复入口和就绪探针。此检查是受保护路径约束，不是管理员对全部业务限流的豁免。

更新采用部分更新语义，省略字段保持原值；服务端以读取时的更新时间进行并发写入检查，发生冲突返回 409，调用方刷新后重试。

## 匹配与执行阶段

### 路径和方法

| 写法 | 匹配语义 |
| --- | --- |
| `/api/users/42` | 精确路径 |
| `/api/users/{id}` 或 `/api/users/:id` | 参数占一个非空路径段 |
| `/api/files/*/content` | 中间的 `*` 占一个路径段 |
| `/api/tree/*` | 该前缀本身及任意层级后缀 |

方法与路径必须同时匹配。路径匹配不读取查询参数或请求体，接口选择器提供的路由模板可直接用于绑定。执行、配置诊断和 Demo 复用 `shared/src/platform/rate-limit.ts` 中的匹配器。

### 身份与规则组合

- 认证前路径阶段选择 IP 或 IP+资源维度规则，防护公开接口及认证入口。
- 身份维度路径规则在管理员、会员或开放应用认证器验证成功后执行，不额外解析 JWT，不信任请求自报的身份。
- 认证前、认证后各选一条启用的匹配路径规则：优先级大者优先，同优先级按规则名稳定排序。
- 路由显式挂载的 `namedRateLimit()` 可叠加业务保护；同一请求内同一规则最多应用一次，身份阶段也只进入一次。不能把所有匹配规则无条件全部叠加。
- 匿名请求不执行身份维度规则，不回退到用户额度。需要同时保护匿名流量时，另配入口 IP 规则。

身份具有明确命名空间：

| 维度 | 计数身份 |
| --- | --- |
| IP | 可信代理解析器得到的来源 IP |
| 管理员 | `u:{tenantId或platform}:{userId}` |
| 会员 | `m:{tenantId或platform}:{memberId}` |
| 开放应用 | `a:{tenantId或platform}:{clientId}` |
| IP+资源 | 来源 IP 加不可逆路径摘要，按具体资源隔离且不保存路径令牌原文 |

身份中的租户归属来自已验证主体；不同身份体系及租户不共用额度。平台租户标记为 `platform`。IP 解析复用可信代理设置，不接受未受信来源伪造的转发头。

### 窗口与模式

主窗口和附加窗口在一次 Redis Lua 执行中完成计数与判定，任一窗口超限即超限。进入计数器的尝试均占用窗口，拒绝后不回退；停用、身份缺失、豁免和已封禁请求不按普通请求增加窗口计数。

固定窗口从首个请求开始计时。滑动窗口使用当前桶与上一桶的加权近似，不提供逐请求精确滑动日志。

`monitor` 记录观察命中并继续请求；`enforce` 超限返回 429。观察模式仍执行临时封禁。修改算法、窗口时长、身份维度、方法、附加窗口规格或路径范围会隔离计数空间；单独调整主窗口上限会应用现有计数，不保证获得全新额度。描述和告警调整不应视为额度清除操作。

## 保存与多实例生效

规则保存先持久化，再尝试刷新当前 API 实例。数据库事务提交通过 `rate_limit_rules` 的触发器发送 `cache_invalidate`，其他实例将缓存标记为失效，并在后续规则访问时重载。刷新采用单飞和失效代次检查，避免并发刷新覆盖新的失效标记。

监听重建时清空缓存新鲜度，另以 30 秒新鲜度检查兜底；不为每个请求查询全部数据库配置。刷新失败保留可用缓存并记录告警，持久化成功不等于所有实例已经加载成功。

管理响应中的 `policyVersion` 是配置快照摘要，`loadState` 表示响应实例缓存是否与该规则配置一致。它不是集群加载确认，也不是数据库乐观锁令牌；多实例部署应结合各实例日志、就绪探针和实际命中验证。

## 权限、故障与响应

### 管理权限

规则是全局资源。多租户模式下所有管理接口额外要求平台管理员，单租户模式按功能权限控制。

| 权限 | 能力 |
| --- | --- |
| `system:rate-limit:view` | 规则、接口目录、匹配诊断、统计、命中记录及封禁列表 |
| `system:rate-limit:manage` | 创建、编辑、启停和删除自定义规则 |
| `system:rate-limit:ban` | 新增和解除临时封禁 |
| `system:rate-limit:reset` | 清除额度和清空统计 |

变更类管理操作经过契约权限和操作审计。匹配诊断不产生真实请求，也不能将模拟身份作为业务授权依据。

### Redis 与 HTTP 响应

判定使用独立 Redis 客户端：连接超时和命令超时均配置为 750 毫秒，关闭离线队列，单请求不重试；客户端尚未就绪时直接进入规则故障策略。该预算约束单次 Redis 操作，不是整个请求处理的耗时保证。

| 场景 | 响应与行为 |
| --- | --- |
| 普通超限或临时封禁 | HTTP 429，带 `Retry-After` 秒数；不执行后续业务处理 |
| 观察命中 | 继续后续链路，最终状态由业务处理决定，不因本规则超限返回 429 |
| 判定故障且 `failMode=open` | 放行并尝试记录故障决策 |
| 判定故障且 `failMode=closed` | HTTP 503，`X-Zenith-Error: rate-limit-unavailable` 和 `Retry-After: 1` |
| 维护模式拦截 | HTTP 503，`X-Zenith-Error: maintenance`；由独立维护中间件处理 |

普通计数响应提供 `RateLimit-Limit`、`RateLimit-Remaining` 和 `RateLimit-Reset`。多窗口选择剩余额度最小的约束，同值选择较小上限；多保护层避免用更宽松余量覆盖已有头。调用方不能仅凭这些头判断集群所有保护层下一次请求一定成功。

429 的等待时间考虑窗口及下一次尝试；并发请求仍可消耗额度，因此 `Retry-After` 是退避建议，不是预约额度。封禁响应以封禁剩余时间计算等待值，不要求携带普通窗口的全部额度头。

上述响应头和 `X-Zenith-Error` 经 CORS 暴露。前端只将带 `maintenance` 标识的 503 识别为维护，其他服务不可用响应保留其错误语义，不触发全站维护展示。

### 敏感信息

限流记录展示路由模板，不写公开链接、会话令牌等路径参数原值。IP+资源维度以路径摘要隔离资源；不能将所有资源改成同一模板计数而改变保护范围。限流链路传递安全路径给 API 访问日志，异常关联使用 `correlationId`，不复制凭证或请求正文到限流记录。

## 临时封禁与运维操作

启用规则内先检查显式临时封禁，再检查普通豁免；封禁优先于观察模式。停用规则不执行该策略，但不会删除仍有效的封禁；到期前重新启用规则时，封禁仍可生效。

封禁作用于规则下的精确计数身份，记录原因、操作人和到期时间。时长为 60 秒至 30 天，由 Redis TTL 自动到期；修改普通计数规格不解除封禁。

| 操作 | 效果 | 保留内容 |
| --- | --- | --- |
| 清除额度 | 删除当前计数规格下该身份的主窗口和附加窗口计数 | 临时封禁、命中记录、统计 |
| 解除封禁 | 删除该规则和身份的显式封禁 | 普通计数及统计；解除后仍可能超限 |
| 清空统计 | 切换该规则统计周期，所有统计视图读取新周期 | 额度、封禁及审计；旧周期按 TTL 回收 |
| 删除规则 | 删除自定义配置并触发缓存失效，内置规则不可删除 | 已生成的有期限运行数据自然到期，不将其视为已清除 |

## 统计、记录与告警

### 统计口径

概览累计最近 24 个小时桶（含当前尚未结束的小时），详情按需读取最近 30 个自然日桶。分桶使用 `APP_TIME_ZONE`，不使用宿主机本地时区。

- `hitCount`：正常放行、普通超限、观察命中、封禁和故障决策合计，不含豁免。
- `blockedCount`：普通超限拒绝与临时封禁合计，不含观察命中。
- `monitoredCount`、`bannedCount`、`exemptCount`、`degradedCount`：分别统计对应决策；故障决策汇总放行与拒绝，不单独拆分二者。
- `blockRate`：实际拦截数除以规则命中数；分母为零时为零。

同一 HTTP 请求可命中多个保护层，规则命中合计不是独立 HTTP 请求数。限流放行只表示继续后续链路，后续业务仍可能返回 4xx 或 5xx。

### 写入、保留与清理

遥测使用每进程最多 2000 条待写队列，每批最多 500 条异步写 Redis，不在请求链逐条写数据库。统计是尽力而为，队列满、进程退出或写入失败可能丢失；`queued`、`dropped` 是响应实例的队列和丢弃指标，不是集群汇总。

| 数据 | 保留与上限 |
| --- | --- |
| 小时桶 | 每桶 25 小时 TTL |
| 日桶 | 每桶 32 天 TTL |
| 近期异常决策 | 每规则最多 500 条，按事件时间最多 7 天；写入淘汰过期成员，读取再次过滤 |
| 当日实际拦截来源 | 最多 1000 个身份，保留 2 天；详情显示 Top 10 |
| 统计周期标记 | 清理时生成，33 天 TTL，活跃批次续期 |

近期记录保存 `blocked`、`monitored`、`banned`、`degraded`，不逐条保留普通放行和豁免。每条有独立 ID，避免同毫秒同来源事件覆盖。记录查询在有界集合内服务端筛选和分页，不提供无限历史审计；完整请求诊断复用现有 API 访问日志和链路能力。

清空统计时小时/日趋势、记录、来源排行同时切换周期。切换前已入队事件不能回灌新周期，清理前后的在飞写入无需逐键扫描删除旧数据。

### 告警

告警只由普通拒绝或封禁触发，不以观察命中触发实际拦截告警。当前小时实际拦截数达到阈值后，通过统一 `notify('ops.rate_limit.spike')` 投递；Redis 冷却闸和通知去重键抑制重复告警。

指定接收人必须是启用且 `tenantId=null` 的平台用户；留空回退到启用的平台 `admin` 用户。发送失败记录告警并尽力释放本轮冷却闸，不将统计视为可靠消息账本。

## 管理页面与匹配诊断

| 区域 | 职责 |
| --- | --- |
| 规则管理 | 按名称、说明、路径、模式及启用状态筛选；显示完整规则、绑定来源和路径匹配数量 |
| 运行概览 | 命中、实际拦截、观察和故障指标、趋势及统计写入状态 |
| 命中记录 | 近期异常决策的规则、身份/安全路由及决策筛选，分页、清额度、封禁和关联日志入口 |
| 临时封禁 | 原因、身份、到期时间及新增/解除操作 |

配置侧栏默认展开基本信息、接口范围和主限额，高级策略、豁免及告警折叠。预设只填充策略，不直接启用；附加窗口时长和上限须一起填写。页面可编辑一个附加窗口，接口最多接受两个，编辑时保留其他已配置附加窗口。

绑定数量仅统计方法与路径匹配到的接口目录项，不包含具名业务挂载；具名规则显示路径匹配数量为零并不表示未生效。

规则摘要与概览、记录、详情分开查询；详情打开后按需加载趋势和来源。统计和相关活跃查询以 30 秒轮询补充刷新，手动刷新有明确反馈，390px 窄屏保留操作入口、折叠内容和固定提交区。

匹配诊断只解释输入方法、路径和模拟主体类型下的路径规则选择，不发送业务请求、不读取或消耗真实额度，也不确认真实身份、当前豁免或封禁。结果明确不涵盖全部具名业务保护；真实请求的授权、并发计数和最终业务状态仍以运行链路为准。

## 接口与实现位置

下表路径均以 `/api/rate-limit` 为前缀，权限完整前缀为 `system:rate-limit:`；多租户平台门禁应用于全部操作。

| 方法 | 路径 | 权限后缀 | 用途 |
| --- | --- | --- | --- |
| GET | `/rules` | view | 完整规则配置与加载状态 |
| POST | `/rules` | manage | 创建自定义规则 |
| PATCH | `/rules/{id}` | manage | 部分更新规则 |
| DELETE | `/rules/{id}` | manage | 删除自定义规则 |
| GET | `/operations` | view | 方法、路径、说明和认证类型目录 |
| POST | `/diagnose` | view | 无副作用路径匹配诊断 |
| GET | `/stats` | view | 规则统计摘要及本实例写入状态 |
| GET | `/rules/{id}/stats` | view | 按需读取规则趋势、记录及来源 |
| GET | `/events` | view | 近期记录；支持 `name`、`keyword`、`decision`、`page`、`pageSize` |
| GET | `/bans` | view | 活跃封禁 |
| POST | `/ban`、`/unban` | ban | 新增或解除精确身份封禁 |
| POST | `/unblock`、`/reset-stats` | reset | 清除额度或切换统计周期 |

实现入口：

- `packages/shared/src/platform/rate-limit-policy.ts`：内置策略单一来源。
- `packages/shared/src/platform/rate-limit.ts`：纯匹配器与公共类型。
- `packages/shared/src/platform/rate-limit-validation.ts`：限流专用校验，避免将配置运行时拖入通用首屏依赖。
- `packages/shared/src/platform/contracts/rate-limit.ts`：方法、路径、权限和响应契约。
- `packages/server/src/middleware/rate-limit.ts`、`src/lib/rate-limit-stage.ts`：计数、阶段调度与生效规则。
- `packages/server/src/lib/rate-limit-redis.ts`、`rate-limit-stats.ts`：有界 Redis 客户端及遥测。
- `packages/server/src/services/platform/rate-limit.service.ts`、`rate-limit-alert.service.ts`：配置、诊断、统计读取和通知。
- `packages/web/src/hooks/queries/rate-limit.ts`、`src/pages/system/rate-limit/RateLimitPage.tsx`：契约访问与页面；Demo 复用相同契约。

## 验收标准

验证模板、通配路径和 HTTP 方法、稳定优先级、同请求去重、跨身份/租户隔离、多窗口并发、配置变更、观察转拦截、封禁与豁免、Redis 超时及恢复、统计周期和事件保留、公开令牌保护、多实例失效传播与重连。前端完成桌面及 390px 下的创建、编辑、诊断、清理和封禁流程，并检查包体积及启动冒烟。

真实 PostgreSQL/Redis 集成验证使用显式隔离 fixture 与独立前缀，结束后清理。测试结论分别记录实际执行、替身和跳过项目，不对已有业务规则施压。
