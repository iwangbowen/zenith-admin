# 导入中心

导入中心统一处理 CSV / XLSX 的文件检查、字段映射、预检、正式导入、重复策略、进度和错误修正。业务定义注册在 `packages/server/src/bootstrap/import-definitions.ts`，HTTP 契约位于 `@zenith/shared/tasks`，执行复用任务中心的 `data-import-preview` 和 `data-import`，不建立独立任务表或队列。

## 标准流程

1. 页面使用 `ImportButton` 或导入中心的「新建导入」选择实体。
2. 文件先以 `restricted` 可见性上传到文件中心。任务只接受当前用户/租户拥有的受控文件。
3. `POST /api/import-jobs/inspect` 读取表头、有效行数、最多 5 行样例和字段映射建议；这一步不创建任务、不写入业务数据。
4. 用户确认目标字段映射和重复策略后提交预检或正式导入。预检只执行解析、业务校验和重复判断，不落库。
5. 成功且无失败行的预检可在进度窗口点击「确认正式导入」，复用同一文件和规格创建正式任务。存在失败行时先修正错误文件；任务级失败则按错误原因处理后恢复或重新提交。
6. 任务按行报告成功、失败或跳过；失败行生成受控错误文件，下载后修正数据再重新上传。业务页面使用同一上传、映射和进度链路；需要上下文的实体从对应业务页面发起，导入中心不能代填资源上下文。

## 文件检查与字段映射

- 文件大小上限为 10 MiB；数据行上限使用实体的 `maxRows`，默认 10,000 行。XLSX 只读取第一个工作表，CSV 按文件名后缀识别；无效文件、缺少工作表或超过预算必须明确报错，不静默截断。
- 第一行为表头；匹配会去除末尾必填星号并规范化大小写、空白及部分分隔符，规范化后重复的表头必须拒绝。空表头列不参与匹配，但不能改变其他源列的实际位置。
- `inspect` 返回实际非空行数、最多 5 行样例及建议映射，不执行业务校验。空行先按原值判断，再做样例脱敏，不能因为掩码或“未映射”占位增加行数；大量格式化空行超过物理行预算时拒绝文件。
- 建议映射使用列的 `header` 与 `aliases`。`fieldMapping` 以目标字段 key 为键、文件表头为值；显式 `null` 表示忽略可选列，省略字段则按标准表头定位。必填映射缺失、未知目标字段、不存在的源列或多个显式映射共用同一源列必须拒绝。
- 敏感列通过 `sensitive: true` 声明，非空样例显示掩码；未知列样例仅显示“未映射”，不能返回原值。文件检查的请求和响应正文均不进入审计记录。
- 正式解析只以映射后的目标列判断有效数据行，检查阶段的行数不能替代任务实际处理数；配置页必须明确显示“共 N 行”，不省略关键计数。

## Definition 约束

`ImportDefinition` 声明稳定的实体、权限、列元数据、上下文校验、预载数据、行解析和落库逻辑。列 `key` 是内部契约，表头 `header` 是文件文案；解析按规范化表头匹配，用户可通过 `fieldMapping` 覆盖映射。必填列缺失、重复表头、空数据和超出行数上限在任务行处理前明确失败。

业务定义使用 `duplicateKeys(row)` 返回全部唯一业务键（如用户名、手机号、邮箱）；只有单一键的实体可使用 `duplicateKey(row)`。预检与正式导入按同一组键判断文件内重复，断点恢复保留已有键与失败行。重复策略包括：

- `error`：重复行进入失败明细并生成错误文件；
- `skip`：重复行标记为跳过，其他行继续处理。

业务校验和数据库唯一约束仍是最终边界；跳过策略不能绕过租户、资源或权限校验。批量导入禁止在前端自行拼接 DTO 或绕过 `useImportUpload`。

`prepare(context)` 负责只读预载及资源级权限校验，执行任务与下载错误文件都会调用，不能写入业务数据。`parseRow` 只做归一与校验；`insertRow` 复用业务 Service，并使用框架当前事务执行器。写入阶段的预期行拒绝使用 `HTTPException(400 / 409)` 或数据库完整性约束；基础设施异常必须中止任务。`finalize` 只在正式导入完成逐行处理后执行，必须允许重复调用，外部副作用交由领域事件或 Outbox。

## 结果与确认

任务的 `success` 表示本轮逐行处理完成，不代表每行都通过。结果中的 `succeeded`、`failed`、`skipped` 分别记录成功、失败和跳过数量；处理完成时三者合计为 `total`。行级明细保留原工作表行号，失败行进入错误文件，跳过行不作为失败行回导。

只有 `data-import-preview` 状态为 `success` 且 `result.failed` 为 0，原创建人才可确认正式导入。确认复用文件、上下文、字段映射和重复策略，创建 `data-import` 任务；正式执行仍会重新校验权限、资源与业务数据，预检结果不构成后续数据状态的锁定。

## 恢复重试与文件生命周期

| 操作 | 当前语义 |
| --- | --- |
| 预检 / 正式导入 | 默认 `maxAttempts=1`，重试计划按提交时的生效任务策略快照保存；预检允许并行，正式导入默认限制同一创建人的未结束同类任务 |
| 断点恢复 | 保留已提交进度、唯一业务键集合、失败行和统计，继续处理剩余行；执行前重新校验当前授权 |
| 重新开始 | 清空进度、检查点、结果与明细，并释放旧错误产物引用；输入文件保留，已提交的业务记录不会回滚，再次处理时仍受重复策略约束 |
| 修正错误行 | 下载错误文件，按错误原因修改后重新上传并检查映射，创建新任务；不修改旧任务结果 |
| 删除 / 保留期清理 | 在删除任务的同一事务内释放输入和错误文件引用；无其他引用的文件由统一 GC 回收 |

正式导入的幂等规格包含实体、文件、上下文、字段映射和重复策略，并按租户、创建者与任务类型隔离。相同规格重放返回原任务且不重复持有文件引用；变更映射或重复策略属于不同规格。预检不复用正式导入的幂等键。

输入文件引用随任务记录保留，任务完成不立即释放，以保证预检确认、恢复和重开可用。错误文件的持有与替换在任务状态结算事务中完成；重开、单个删除、批量删除和保留期清理均经过统一生命周期钩子，不能仅删除任务行或直接删除底层文件。

## 安全与任务边界

- 上传文件和错误文件使用受控可见性，只能通过导入任务的权限和租户边界读取；不使用通用公开文件内容接口。
- `fileId`、实体权限、上下文和映射在提交与任务执行阶段都复验；任务 payload 不接受客户端伪造 `dryRun` 改变 handler 注册类型。
- 预检与正式导入是不同任务类型。预检不占正式导入互斥额度，不写业务数据；确认接口只接受成功且无失败行的预检任务。
- 行级写入、成功明细与检查点在同一受执行权 fencing 保护的事务中提交；基础设施异常中止任务，不伪装成普通失败行。创建任务和持有输入文件引用同事务，幂等重放不重复增加引用，映射或重复策略变化视为不同规格。
- 执行前从数据库重建创建人的启用状态、有效角色和当前权限，并复验任务租户是否有效。普通用户租户变更后拒绝执行；平台管理员按任务持久化的目标租户执行，不能使用当前页面的切换状态。文件检查和提交还必须匹配上传者与精确租户。
- 确认与错误文件下载只允许原创建人，管理员可查看任务不等于可代为确认或下载。下载还需复验当前实体权限，并通过 `prepare(context)` 检查关联资源访问权。
- 错误文件只包含失败行的导入目标字段原值和错误原因，不额外写入授权上下文或内部凭证；它用于修正回导，不能当作脱敏预览文件。下载经导入任务接口，不暴露底层存储地址，通用公开文件内容接口不能读取。

## 前端验收

导入配置必须能清楚区分“上传中”“读取表头中”“读取失败”“已读取 N 行”和“提交任务中”，失败状态提供重试。字段映射必须显示必填标记并阻止缺少必填映射时提交；重复策略需要明确文案。预检完成后展示行级结果，仅满足确认条件时展示「确认正式导入」；存在失败行及错误文件时提供受控下载和重新上传入口。

窄屏下配置弹窗、映射列表和行级明细可滚动且不产生页面横向溢出。导入完成后，发起页面只失效实际受影响的业务列表；任务历史和行级明细继续由任务中心查询。

## 契约与接口

| 操作 | 路径 | 作用 |
| --- | --- | --- |
| entities | `GET /api/import-jobs/entities` | 按权限返回可导入实体与列元数据 |
| template | `GET /api/import-jobs/{entity}/template` | 下载数据页仅含表头、独立填写说明页及枚举下拉的模板 |
| inspect | `POST /api/import-jobs/inspect` | 读取表头、样例、行数和映射建议 |
| submit | `POST /api/import-jobs` | 提交预检或正式导入任务 |
| confirm | `POST /api/import-jobs/{id}/confirm` | 确认成功预检并创建正式任务 |
| error-file | `GET /api/import-jobs/{id}/error-file` | 下载受控错误行文件 |

模板数据页只保留表头，示例和填写说明放在独立说明页，不将示例作为待导入记录。字段映射、文件预算和样例展示统一遵循前述文件检查规则。

任务详情、取消、断点恢复、重试和行级明细统一使用 `/api/async-tasks/*`。
