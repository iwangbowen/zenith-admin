# IP 访问控制

IP 访问控制是平台级 API 接入策略，管理页面为 `/system/ip-access`。黑白名单由运行时设置模块 `ipAccess` 统一保存，
来源检测、草稿诊断和拦截日志分别提供管理接口。配置存储、版本和缓存机制复用[运行时设置](./settings.md)。

## 策略语义

- 中间件挂载在 `/api/*`，包含登录、验证码、OAuth、公开业务 API 及 WebSocket 握手，不按匿名访问属性豁免。请求仍需经过 CORS、CSRF、请求体限制等前置中间件。
- 非 API 的 HTML、CMS、短链及静态资源，以及已经建立的 WebSocket 消息不在中间件范围；需要网络级保护时在网关实施。
- 黑名单命中优先拒绝；白名单启用时，只有命中白名单且未命中黑名单的来源可以访问。两者关闭时放行。
- 启用白名单必须至少包含一个合法地址，每个名单最多 1000 条。IPv4、IPv6 与 CIDR 统一规范化、清理主机位并去重。
- IPv4 仅接受四段十进制，不接受省略、八进制及十六进制形式。IPv6 不接受 zone ID；IPv4 映射 IPv6 转为等价 IPv4，映射 CIDR 前缀必须不少于 96 位。
- 来源地址由 `getClientIp()` 读取；仅当 TCP 对端属于 `TRUSTED_PROXY_CIDRS` 时信任转发头，并从右向左跳过可信代理。非可信对端使用 TCP 地址，页面不能修改可信代理。
- 策略启用且来源无效时拒绝。策略无法加载或文档解析降级时返回 503，不能把损坏策略视为关闭。已有缓存按设置运行时的 SWR 规则使用，跨实例失效复用数据库通知。

## 权限与保存

| 能力 | 权限 |
| --- | --- |
| 读取配置、历史、版本比较、来源检测与草稿诊断 | `system:ip-access:view` |
| 保存配置、恢复预览、确认恢复 | `system:ip-access:update` |
| 查询拦截日志和当前实例日志缓冲状态 | `system:ip-access:log` |

多租户部署额外要求平台管理员身份；租户的设置模块清单和菜单不提供此专用页面入口。单租户按权限码授权。

读写使用统一 `GET/PUT /api/settings/ip-access`。黑白名单构成同一原子版本，写入携带 `{ baseToken, overrides, note? }`；
省略的字段继承默认值，数组整体替换。保存和版本恢复在持锁事务中校验基线、完整生效文档与当前服务端观察到的来源 IP。
拒绝会阻断操作者的配置，直接 API 调用和版本恢复执行相同检查。历史读取、比较及恢复协议见[运行时设置 API](./settings.md#api)。

页面采用无卡片布局：来源与草稿摘要、版本工具、黑白名单设置直接按区块排布；支持逐行错误定位、规范化去重、加入当前 IP 和重叠提示。
匹配诊断与误配置恢复默认折叠，校验和自锁错误直接显示。拦截类型筛选完整显示占位、选中值和下拉选项；低频说明不挤占主要配置区域。

## 诊断

| 方法与路径 | 请求 / 响应 |
| --- | --- |
| `GET /api/ip-access/context` | 返回 `clientIp`、`version`、`baseToken` 和已生效策略的 `decision` |
| `POST /api/ip-access/diagnose` | 请求为 `{ policy, baseToken, ip? }`；`ip` 仅允许单个合法 IP，省略时使用当前来源 |

诊断响应包含 `clientIp`、`testedIp`、`version`、`baseToken`，以及草稿对测试来源的 `decision`、对当前操作者的 `currentDecision`。
判定字段为 `allowed`、`reason`、`matchedEntry`；原因取值为 `disabled`、`invalid-ip`、`blacklist`、`whitelist` 或 `default`。
`whitelist` 需结合 `allowed` 区分命中放行与未命中拒绝。没有命中条目时 `matchedEntry` 为 `null`。

诊断与执行共用 `evaluateIpAccess()`，不保存配置、不产生拦截日志。版本变化返回 409；草稿、测试来源或服务端版本变化后，页面标记旧结果过期。
诊断不授予保存权限，也不能替代提交时的权威校验。

## 拦截日志

`ip_access_logs` 包含来源、HTTP 方法、安全路由模板、原因、命中地址、策略版本、请求 ID、User-Agent 与时间。
路径中的动态参数记录为模板，不保留真实令牌；原始查询和请求体不写入拦截日志，未匹配路径记录为 `/api/[unmatched]`。
`blockType` 为 `blacklist`、`whitelist` 或 `invalid-ip`；未命中白名单或来源无效时没有命中地址。策略与版本来自同一运行时快照。

日志复用有界批量缓冲：最多等待 2000 条、单批 100 条、单个在途写入，首批在 50ms 后异步提交。溢出和失败批次丢弃并累计计数，不无限重试；优雅停机尝试排空。该日志不是完整流量统计，进程崩溃时可能丢失未落库记录。

`GET /api/ip-access-logs` 支持 `ip` 关键字、`blockType`、`startTime` / `endTime` 和分页参数。页面详情显示命中依据和请求 ID。
`GET /api/ip-access/log-health` 返回 `accepted`、`stored`、`dropped`、`flushFailures`、`pending`、`flushing`，只代表当前应答 API 实例，
不提供集群累计量；进程重启后计数重置。页面展示待写与丢弃量，发生丢弃时提示记录不完整。
日志留存由[数据保留](./data-retention.md)中的 `ip_access_logs` 策略管理，默认 90 天。

## 受控恢复

仍可访问后台时使用版本历史或“停用访问控制”：停用操作先填入关闭草稿，保存后才生效，未提交前不会改变运行策略。
版本恢复需要预览、填写说明并确认，保存执行相同的自锁检查。

来源变更导致无法访问时，在项目根目录、使用目标服务的数据库与运行环境执行：

```bash
npm run ip-access:recover -w @zenith/server -- --actor-id 1 --reason "来源网络调整，恢复管理访问" --confirm-disable
```

`--actor-id` 必须替换为实际操作者的平台超级管理员 ID；示例中的 `1` 不是默认授权。

命令要求操作者账号启用、属于平台并持有启用的 `super_admin` 角色；`--reason` 为 1–450 字的非空恢复原因，`--confirm-disable` 必填。
本地开发预先设置 `NODE_ENV=development`；生产使用实际运行环境变量，不能使用开发模式。
命令经统一设置事务恢复版本 0 的默认关闭策略，配置发生变化时创建记录操作者、说明和恢复来源的新版本；已经处于相同默认覆盖状态时不创建空版本。
并发变化返回冲突，需要重新执行；不提供 HTTP 绕过入口，不自动恢复旧策略。

## 错误语义

| 状态码 | 含义 |
| --- | --- |
| 400 | IP/CIDR 不合法、启用空白名单、自锁变更、诊断 IP 不是单个地址或其它入参无效 |
| 401 | 管理接口缺少有效认证 |
| 403 | API 请求被 IP 策略拒绝，或管理接口权限 / 平台身份不足；应结合响应文案区分 |
| 409 | 保存、恢复或诊断使用的编辑基线已失效，需读取最新版本 |
| 503 | IP 策略无法加载或有效文档无法被安全解析，需恢复策略或排查基础设施 |

## 验证要求

覆盖 IPv4/IPv6/CIDR 边界、映射地址、非法地址、空白名单、重叠、登录与公开接口、握手、可信代理链、自锁保存与恢复、租户越权、并发冲突、异常策略 503、日志脱敏与有界突发写入。页面回归包含名单编辑、诊断过期、保存、版本恢复、日志筛选和窄屏布局。Demo 共用契约与策略纯函数。
