# IP 访问控制

IP 访问控制是平台级 API 接入策略，配置由运行时设置模块 ipAccess 统一管理，页面位于 /system/ip-access。

## 策略语义

- 所有 /api/* 请求统一执行策略，包含登录、验证码、OAuth、公开业务 API 及 WebSocket 握手，没有基于匿名访问属性的隐式豁免。
- 非 API 的 HTML、CMS、短链及静态资源，以及已经建立的 WebSocket 消息不在中间件范围；需要网络级保护时在网关实施。
- 黑名单命中优先拒绝；白名单启用时，只有命中白名单且未命中黑名单的来源可以访问。两者关闭时放行。
- 启用白名单必须至少包含一个合法地址，每个名单最多 1000 条。IPv4、IPv6 与 CIDR 统一规范化、清理主机位并去重。
- IPv4 仅接受四段十进制，不接受省略、八进制及十六进制形式。IPv6 不接受 zone ID；IPv4 映射 IPv6 转为等价 IPv4，映射 CIDR 前缀必须不少于 96 位。
- 来源地址由 getClientIp() 读取；仅当 TCP 对端属于 TRUSTED_PROXY_CIDRS 时信任转发头，页面不能修改可信代理。
- 策略启用且来源无效时拒绝。策略无法加载或文档损坏时返回 503，不能静默使用关闭策略的默认值。缓存和跨实例失效沿用设置运行时。

## 权限与保存

多租户部署仅平台管理员访问配置、历史、诊断和全局日志；单租户分别按 system:ip-access:view、system:ip-access:update、system:ip-access:log 授权。

读写继续使用统一 GET/PUT /api/settings/ip-access，不提供第二套设置写接口。黑白名单是同一原子版本，使用 baseToken 并发指纹。保存和版本恢复在事务内再次检查当前服务端来源 IP，拒绝会阻断操作者的配置，不能通过直接 API 调用或历史恢复绕过。

页面提供来源与草稿摘要、逐行错误定位、规范化去重、加入当前 IP 和重叠提示。诊断和恢复说明默认折叠，校验及自锁错误直接显示。

## 诊断

- GET /api/ip-access/context 返回服务端观察到的当前 IP 及已生效策略判定。
- POST /api/ip-access/diagnose 接收草稿、编辑基线 baseToken 和可选的单个测试 IP；省略时测试当前来源。
- 返回测试来源和当前操作者的判定、命中地址、版本与基线，不保存、不产生拦截日志。
- 诊断与执行共用 evaluateIpAccess()。版本变化返回 409；草稿、测试来源或版本变化后页面标记旧结果过期。保存仍需权威校验。

## 拦截日志

ip_access_logs 包含来源、方法、安全路由模板、原因、命中地址、策略版本、请求 ID、User-Agent 与时间。不保存 URL 令牌、原始查询或请求体；未匹配路径统一记录 /api/[unmatched]。

日志复用有界批量缓冲：最多等待 2000 条、单批 100 条、单个在途写入，首批在 50ms 后异步提交。溢出和失败批次丢弃并累计计数，不无限重试；优雅停机尝试排空。该日志不是完整流量统计，进程崩溃时可能丢失未落库记录。

GET /api/ip-access-logs 支持来源、原因及时间范围筛选。页面详情显示命中依据和请求 ID。GET /api/ip-access/log-health 返回当前 API 实例的缓冲状态，不能作为集群累计量。留存由统一数据保留策略管理，默认 90 天。

## 受控恢复

仍可访问后台时使用版本历史或停用草稿；保存同样执行当前安全检查。来源变更导致无法访问时，在服务器工作目录执行 npm run ip-access:recover -w @zenith/server -- --actor-id 1 --reason "来源网络调整，恢复管理访问" --confirm-disable。

命令使用实际运行环境变量。本地开发需预先设置 NODE_ENV=development；生产不使用开发模式。必须提供明确确认、有效的平台超级管理员 ID 和恢复原因。命令经统一设置事务恢复默认关闭策略，创建记录操作者、说明和恢复来源的新版本。并发变化时失败，需重新执行；不暴露 HTTP 绕过入口，不自动恢复旧策略。

## 验证要求

覆盖 IPv4/IPv6/CIDR 边界、映射地址、非法地址、空白名单、重叠、登录与公开接口、握手、可信代理链、自锁保存与恢复、租户越权、并发冲突、异常策略 503、日志脱敏与有界突发写入。页面回归包含名单编辑、诊断过期、保存、版本恢复、日志筛选和窄屏布局。Demo 共用契约与策略纯函数。
